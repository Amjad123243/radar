# رادار الفيوتشر PRO

أداة تحليل ومحاكاة لعقود **Binance USDT-M Futures** الدائمة، بتشتغل بالكامل بالمتصفح من ملف واحد: `futures-radar.html`.

بتعطي إشارات دخول وخروج، وخطة صفقة بتلات أهداف، وتحليل متعدد الفريمات، وماسح للسوق، وبيانات الفيوتشر (OI، ونسب اللونغ/شورت)، وباك تيست، ومحسّن إعدادات، وسجل صفقات حقيقية، ووكيل ذكاء اصطناعي (Claude)، ووكيل تداول ورقي بيتعلم من دروسو.

> ⚠️ **أداة تحليل تعليمية، مو نصيحة مالية.** الأداة **ما بتفتح صفقات** وما بتحتاج مفتاح Binance أبداً. نتائج الباك تيست على الماضي ما بتضمن المستقبل.

## 1. التشغيل والنشر

### المتطلبات
- متصفح حديث (Safari على iPad/iPhone، أو Chrome/Edge/Firefox).
- اتصال بالإنترنت يوصل لـ `fapi.binance.com` و `fstream.binance.com` و `cdn.jsdelivr.net` و `fonts.googleapis.com`.
- (اختياري) مفتاح Anthropic API لتشغيل الوكيل.

### النشر على GitHub Pages
1. ارفع `futures-radar.html` (و `README.md`) لمستودع عام، مثلاً `radar`.
2. **Settings ← Pages ← Deploy from a branch ← main / (root) ← Save**.
3. الرابط: `https://USERNAME.github.io/radar/futures-radar.html`.
4. على iPad: زر المشاركة ← **Add to Home Screen**.

### التحديث
ارفع الملف الجديد **بنفس الاسم** (Add file ← Upload files ← Commit). بعد دقيقة أو دقيقتين حدّث الصفحة. الإعدادات والسجل والمفتاح بيضلوا، لأنهن محفوظين بالمتصفح ومو بالملف.

### التشغيل المحلي
على الكمبيوتر بيكفي تفتح الملف بالمتصفح (دبل كليك). على iPad **ما بيشتغل** من تطبيق الملفات، لأن المعاينة بتوقف الجافاسكربت، فلازم GitHub Pages أو أي استضافة.

## 3. مصادر البيانات

كل طلبات Binance **عامة** وما بتحتاج مفتاح. الثابت `API = "https://fapi.binance.com"`.

### REST

| الطلب | الاستعمال | الدالة |
|---|---|---|
| `GET /fapi/v1/klines?symbol&interval&limit` | الشموع (1000 للشارت، 300 للفريمات، 500 للماسح، 1500 للمحسّن) | `fetchKlines` |
| `GET /fapi/v1/premiumIndex?symbol` | الفاندينغ | `fetchFunding` |
| `GET /fapi/v1/ticker/24hr?symbol` | السعر والتغير والأعلى والأدنى والحجم خلال 24 ساعة | `fetchTicker` |
| `GET /fapi/v1/ticker/24hr` (كل العملات) | ترتيب أعلى 25 عملة بالحجم | `scanAll` |
| `GET /fapi/v1/exchangeInfo` | قائمة عقود USDT الدائمة الشغالة (للبحث) | `loadSymbols` |
| `GET /fapi/v1/ticker/price` (كل العملات) | الأسعار الحالية لصفقات السجل المفتوحة | `jPrices` |
| `GET /futures/data/openInterestHist` | تاريخ الـ Open Interest | `loadFlow` |
| `GET /futures/data/topLongShortPositionRatio` | نسبة لونغ/شورت عند كبار المتداولين | `loadFlow` |
| `GET /futures/data/globalLongShortAccountRatio` | نسبة لونغ/شورت عند كل الحسابات | `loadFlow` |
| `GET /futures/data/takerlongshortRatio` | نسبة الشرا/البيع (Taker) | `loadFlow` |

### WebSocket
```
wss://fstream.binance.com/market/stream?streams=<sym>@kline_<tf>/<sym>@ticker
```
بيحدّث الشمعة الحالية والتيكر لحظياً، وبيرجع يتصل لحالو بعد 3 ثواني إذا انقطع.

> Binance نقلت بثوث الشموع والتيكر لمسار `/market`، والعنوان القديم (بدون `/market`) بطّل يبعتهن من 23 نيسان 2026.

**احتياط:** إذا ما وصل تحديث من البث خلال 10 ثواني، الأداة بتسحب آخر شمعتين والتيكر عن طريق REST كل 4 ثواني (`applyBar`)، فالشارت ما بيوقف حتى لو البث مقطوع. ولما ترجع للصفحة بعد ما تكون بالخلفية، بتحدّث فوراً وبتعيد الاتصال.

### Anthropic
```
POST https://api.anthropic.com/v1/messages
headers: x-api-key, anthropic-version: 2023-06-01,
         anthropic-dangerous-direct-browser-access: true
```
الطلب بيروح **مباشرة من المتصفح**. الموديل الافتراضي `claude-sonnet-5`، و `max_tokens: 1800`.

### الوضع التجريبي
إذا فشل أول طلب لـ Binance، بيصير `online = false` وبتشتغل `demoKlines()`، اللي بتولّد شموع وهمية ثابتة لكل عملة وفريم. بيطلع شريط أصفر، والنقاط بتصير صفرا، وبيانات الفيوتشر بتتوقف.

## 4. التخزين المحلي

كل شي محفوظ بـ `localStorage` **على نفس الجهاز والمتصفح بس**، عن طريق `store.get` و `store.set` (محميين بـ try/catch).

| المفتاح | المحتوى |
|---|---|
| `frp_params` | الإعدادات العامة (`P`) |

## 5. الحالة والإعدادات

### `DEFAULTS` (الإعدادات الافتراضية)

| المفتاح | القيمة | المعنى |
|---|---|---|
| `emaFast` / `emaSlow` / `emaTrend` | 9 / 21 / 200 | المتوسطات الأسية |
| `crossLook` | 3 | التقاطع لازم يكون صار خلال آخر N شمعات |
| `rsiLongMin` / `rsiLongMax` | 50 / 70 | مجال RSI للونغ |
| `rsiShortMin` / `rsiShortMax` | 30 / 50 | مجال RSI للشورت |
| `minAdx` | 18 | أقل قوة ترند |
| `useTrend` / `useMacd` / `useSar` | ✓ / ✓ / ✗ | فلاتر إضافية |
| `slAtr` | 1.5 | الستوب = ATR × هالرقم |
| `tp1R` / `tp2R` / `tp3R` | 1 / 2 / 3 | الأهداف بوحدات R (مسافة الستوب) |
| `breakeven` | ✓ | نقل الستوب للدخول بعد الهدف 1 |
| `capital` / `lev` / `riskPct` / `fee` | 1000 / 10 / 1 / 0.04 | رأس المال، وأقصى رافعة، والمخاطرة بكل صفقة %، ورسوم كل طرف % |

### طبقات الإعدادات
```
P  = DEFAULTS + frp_params                  // الإعدادات العامة
PP(sym, tf) = P + PROF["sym|tf"]            // مع الإعدادات المخصصة إن وجدت
CP = PP(S.symbol, S.tf)                     // الإعدادات الحالية (refreshCP)
```
`PKEYS` هي المفاتيح اللي بيغيرها المحسّن: `emaFast, emaSlow, emaTrend, slAtr, tp1R, tp2R, tp3R, useMacd, minAdx`.

### الحالة `S` (أهم الحقول)
`symbol, tf, candles[], mode ("live"|"demo"), ws, A (نتيجة analyze), ticker, funding, flow, mtf{}, scan, symbols[], chartType, ind{}, notif, prices{}`

## 6. المؤشرات

كل الدوال بتاخد مصفوفة وبترجع مصفوفة بنفس الطول، مع `null` للقيم اللي لسا ما بتنحسب.

| الدالة | الحساب |
|---|---|
| `ema(src, p)` | أول قيمة = SMA لأول p قيم، وبعدين `k = 2/(p+1)` |
| `rsi(src, 14)` | Wilder: متوسط الربح والخسارة، و `100 − 100/(1+RS)` |
| `atr(c, 14)` | Wilder لـ True Range |
| `adx(c, 14)` | +DI و −DI و DX و ADX (Wilder) |
| `psar(c, .02, .2)` | Parabolic SAR، وبيرجع `{sar[], dir[]}` (1 صاعد، −1 هابط) |
| `boll(src, 20, 2)` | الوسط ± 2 انحراف معياري |
| MACD | `EMA12 − EMA26`، والإشارة = EMA9، والهستوغرام = الفرق |
| `heikin(c)` | شموع هايكن آشي (للعرض بس) |
| `srLevels(c, atr)` | قمم وقيعان (5 شمعات من كل جهة) من آخر 300 شمعة، بيجمّعهن إذا الفرق ≤ ATR/2، وبيرجع أقرب 3 مقاومات و3 دعوم |

## 7. محرك الإشارات

`analyze(c, P, light)` بتحسب المؤشرات والإشارات والباك تيست. `light=true` بتتخطى Bollinger (للماسح والمحسّن).

**مهم:** آخر شمعة (`n−1`) لسا عم تتشكل، فالإشارات بتنحسب لحد `A.last = n−2` بس (آخر شمعة مسكّرة). هيك ما بتطلع إشارة وبعدين بتختفي.

### شروط اللونغ (كلهن لازم يتحققوا)
| الشرط | المعنى |
|---|---|
| `cross` | EMA السريع قطع البطيء لفوق خلال آخر `crossLook` شمعات |
| `stack` | EMA السريع > البطيء |
| `trend` | الإغلاق > EMA الترند (إذا `useTrend`) |
| `rsi` | RSI بين `rsiLongMin` و `rsiLongMax` |
| `macd` | الهستوغرام > 0 وعم يطلع (إذا `useMacd`) |
| `adx` | ADX ≥ `minAdx` |
| `sar` | SAR تحت السعر (إذا `useSar`) |

الشورت هو العكس بالضبط. الإشارة (`A.sig[i] = 1 | −1`) بتطلع **بس بأول شمعة** بتتحقق فيها الشروط، لحتى ما تتكرر.

## 8. قوة الترند (`biasAt`)

نقاط من −90 لـ +90:

| العامل | النقاط |
|---|---|
| السعر فوق/تحت EMA الترند | ±20 |
| EMA السريع فوق/تحت البطيء | ±15 |
| ميل EMA البطيء (آخر 5 شمعات) | ±10 |
| RSI: `clamp((RSI−50)/20) × 15` | ±15 |
| إشارة هستوغرام MACD | ±10 |
| اتجاه هستوغرام MACD | ±10 |
| اتجاه SAR | ±10 |

بعدين بتنضرب بمعامل ADX: ≥30 → 1.1، ≥22 → 1، ≥16 → 0.85، غير هيك → 0.7.

`str = |النقاط| / 90 × 100 × المعامل` (من 0 لـ 100)، وإذا `str < 25` الاتجاه **محايد**.
التسمية: ≥65 **قوي**، ≥45 **متوسط**، غير هيك **ضعيف**.

## 9. الباك تيست (`backtest`)

| القاعدة | التفاصيل |
|---|---|
| الدخول | على **افتتاح الشمعة اللي بعد الإشارة** |
| الستوب | `entry ∓ slAtr × ATR` (ATR تبع شمعة الإشارة) |
| الأهداف | `entry ± risk × tpNR`، وبيطلع تلت الكمية على كل هدف |
| الحجم | `qty = min(رصيد × riskPct% / مسافة الستوب، رصيد × lev / الدخول)` مع إعادة استثمار الربح |
| التعادل | بعد الهدف 1 الستوب بيصير على سعر الدخول (إذا `breakeven`) |
| نفس الشمعة | إذا الستوب والهدف انضربوا بنفس الشمعة، **بتنحسب ستوب** (الأسوأ) |
| الإشارة العكسية | بتسكّر الباقي على الإغلاق، وبتفتح بالاتجاه العكسي |
| الرسوم | `qty × (دخول + خروج) × fee%` |

**النتيجة:** `{trades[], open, pending, eqPts[], stats:{n, win, net, pf, dd, avgR}}`. كل صفقة إلها `R = الربح / (الكمية × مسافة الستوب)`.

## 10. خطة الصفقة (`plan`)

بالأولوية:
1. **`open`**: في صفقة مفتوحة بالمحاكاة، فبتعرض مستوياتها.
2. **`new`**: آخر شمعة مسكّرة فيها إشارة، والدخول على افتتاح الشمعة الحالية.
3. **`bias`**: ما في إشارة بس قوة الترند ≥ 45%، فبتطلع خطة من السعر الحالي مكتوب عليها "مو إشارة مؤكدة".
4. غير هيك: **استنى**.

وبتحسب كمان: `notional` (حجم المركز)، و `levNeed` (الرافعة اللازمة، ومحدودة بـ `lev`)، و `rr` (نسبة الهدف 3).
تحذيرات بيانات الفيوتشر بتطلع من `flowWarnings(dir)`.

## 11. التحليل متعدد الفريمات (MTF)

`MTF = ["1d","4h","1h","15m","5m","1m"]`. لكل فريم: 300 شمعة، و `analyze(light)` بإعدادات `PP(sym, tf)`، وبنحفظ `{bias, sig, rsi}`. بيتحدث كل 60 ثانية.

`mtfConfluence()` بتعدّ كم فريم متفق مع اتجاه الفريم الحالي. وجملة الخلاصة بتعتمد على الفريمات الكبيرة (1D و 4H و 1H) ومجموع الصاعد والهابط.

## 12. البحث التلقائي (الماسح)

- **المصدر:** أعلى 25 عملة بحجم التداول (`quoteVolume`) أو قائمتي.
- لكل عملة: 500 شمعة على فريم الماسح، و5 طلبات بالتوازي (`pool`).
- **الفلتر:** `bias.str ≥ minStr` واتجاه مو محايد.
- **الترتيب:** اللي عندها إشارة جديدة أول، بعدين حسب القوة.
- **التلقائي:** بيفحص مرة مع كل شمعة جديدة (بيشيك كل 15 ثانية)، وبينبّه بالإشارات الجديدة بس.

## 13. بيانات الفيوتشر

`loadFlow()` بتشتغل مع كل تحميل عملة وكل دقيقتين. الفترة من `FPER` (فريم 1m بياخد 5m لأن Binance ما بتعطي أصغر).

| القيمة | الحساب |
|---|---|
| `oi` / `oiChg24` | قيمة الـ OI بالدولار وتغيرها خلال 24 ساعة |
| `oiChgS` / `pxChgS` | تغير الـ OI والسعر خلال آخر 6 فترات |
| `taker` / `takerAvg` | نسبة الشرا/البيع، الأخيرة ومتوسط آخر 6 |
| `top` / `glob` | لونغ/شورت عند الكبار وعند كل الحسابات |

### القراءة

| الحالة | التفسير | النقاط |
|---|---|---|
| سعر ↑ و OI ↑ | لونغات جديدة، صعود قوي | +1 |
| سعر ↑ و OI ↓ | إغلاق شورتات، صعود ضعيف | 0 |
| سعر ↓ و OI ↑ | شورتات جديدة، هبوط قوي | −1 |
| سعر ↓ و OI ↓ | تصفية لونغات، الهبوط ممكن يهدى | 0 |
| متوسط Taker > 1.08 / < 0.92 | ضغط شرا / بيع | +1 / −1 |
| كل الحسابات > 2.5 / < 0.7 | ازدحام لونغ / شورت (`crowd`) | تحذير |
| كبار لونغ والجمهور شورت (أو العكس) | إشارة معاكسة للجمهور | معلومة |
| فاندينغ > 0.05% / < −0.03% | سوق محمّى | تحذير |

العتبات: سعر ±0.1% و OI ±0.5%.

## 14. محسّن الاستراتيجية

### الشبكة (`GRID`) = 864 تركيبة
```
EMA:     [9,21] [12,26] [5,13] [20,50]
Trend:   50, 100, 200
SL×ATR:  1, 1.5, 2, 2.5
TPs(R):  [1,2,3] [1,1.5,2.5] [1.5,2.5,4]
MACD:    ✓ / ✗
ADX≥:    0, 20, 25
```

### الطريقة (Walk-forward بسيط)
1. 1500 شمعة. الـ 70% الأولى **تدريب**، والـ 30% الأخيرة **اختبار** (حسب وقت دخول الصفقة).
2. لكل تركيبة: `analyze` على كل البيانات، وبعدين بتنقسم الصفقات.
3. `rStats` بتحسب بوحدات R: العدد، ونسبة الربح، ومجموع R، و PF، وأقصى تراجع.
4. **الترتيب حسب التدريب:** `score = sumR − 0.5 × ddR`، ولازم يكون عدد الصفقات ≥ `max(6, n/150)`.
5. **النجاح بالاختبار:** عدد الصفقات ≥ `max(3, 35% من الحد)`، ومجموع R > 0، و PF > 1.
6. **التوصية:** أحسن تركيبة بالتدريب **ونجحت بالاختبار**.

زر "طبّق" بيحفظ `PKEYS` بـ `PROF["sym|tf"]`. والتنفيذ بدفعات من 24 تركيبة لحتى ما تعلق الواجهة.

## 15. سجل الصفقات

### شكل الصفقة
```js
{ id, sym, dir: 1|-1, entry, sl, tp, margin, lev,
  tOpen, exit|null, tClose|null,
  src: "signal"|"ai"|"bias"|"manual", note }
```

### الحساب (`jCalc`)
```
qty  = margin × lev / entry
pnl  = qty × (exit − entry) × dir − qty × (entry + exit) × fee%
pctM = pnl / margin × 100          // نسبة من الهامش
R    = (exit − entry) × dir / |entry − sl|
```
الصفقات المفتوحة بتنحسب على السعر الحالي (بيتحدث كل 30 ثانية).

**الإحصائيات:** عدد المسكّرة، ونسبة الربح، والصافي، و PF، ومتوسط R، ونسبة الربح باللونغ وبالشورت، وأحسن وأسوأ عملة، وعدد المفتوحة.

## 22. حدود معروفة

- **الباك تيست تقريبي:** ما فيه انزلاق سعر (slippage) ولا فاندينغ، والتنفيذ داخل الشمعة بيفترض الأسوأ.
- 1500 شمعة على 15m حوالي 15 يوم بس. النتيجة ممكن تتغير كتير مع الوقت.
- المحسّن ممكن "يحفظ الماضي" (overfitting) حتى مع فترة الاختبار. أعد التحسين كل أسبوع أو اتنين.
- بيانات `/futures/data/*` بتغطي آخر 30 يوم بس.
- iPad/iOS: ما في إشعارات بالخلفية، والصفحة بتوقف لما تتسكّر الشاشة.
- ما في ربط تداول: الأداة ما بتعرف صفقاتك الحقيقية إلا إذا سجلتها بالسجل.
- كل الحسابات بالمتصفح، والمحسّن ممكن ياخد 5 لـ 20 ثانية على أجهزة أبطأ.

## 24. الوكيل الورقي (Paper Trading Agent)

الوكيل بيتداول **صفقات وهمية** على أسعار Binance الحقيقية، وبيتعلم من نتايجو عن طريق **ذاكرة دروس**. الموديل نفسو ما بيتغير، بس الدروس بتنبعتلو مع كل قرار.

### الدورة (`botCycle`)
بتشتغل مرة مع كل شمعة جديدة على فريم الوكيل (`botTick` بيشيك كل 15 ثانية)، أو يدوياً بزر "دورة هلق":
1. **تحديث الصفقات المفتوحة:** بيجيب الشموع من آخر شمعة انحسبت (لحد 1500)، فإذا كانت الصفحة مسكّرة، بيلحق شو صار. نفس قواعد الباك تيست: الستوب أول إذا انضرب مع هدف بنفس الشمعة، وتلت على كل هدف، والستوب للدخول بعد الهدف 1. وبيحسب كمان MFE و MAE (بوحدات R).
2. **الدروس:** لكل صفقة AI انسكّرت، بيسأل `SYS_LESSON` (حد أقصى 2 بالدورة)، وبيحفظ آخر 25 درس.
3. **الفحص:** قائمتي أو أعلى 25 عملة، 300 شمعة لكل وحدة.
4. **بوت الإشارات (للمقارنة):** بيفتح على كل إشارة جديدة من محرك القواعد، بدون AI.
5. **قرارات الوكيل:** المرشحين هنن العملات اللي فيها إشارة جديدة أو قوة ترند ≥ `minStr`، وما عندها صفقة مفتوحة. بيسأل عن 2 بالدورة كحد أقصى.

### سياق القرار (`botCtx`)
آخر 30 شمعة، والمؤشرات، واتجاه الفريم الحالي والأكبر (`HTF`: 5m→1h، 15m→1h، 30m→4h، 1h→4h، 4h→1d)، والدعوم والمقاومات، والفاندينغ، وحالة محرك القواعد وباك تيست العملة، والرصيد والصفقات المفتوحة، وسجل الوكيل (آخر 10 صفقات)، و**آخر 15 درس**.

### التحقق قبل الفتح
بيرفض الصفقة إذا: الثقة < 60، أو ما في ستوب، أو الستوب بالجهة الغلط، أو مسافتو برا 0.15% لـ 10%، أو أقل من 3 أهداف، أو هدف بالجهة الغلط. الرافعة محصورة بين 1 و `lev`. الدخول ماركت على آخر سعر.

### الحجم
`qty = min(الرصيد × risk% / مسافة الستوب، الرصيد × الرافعة / الدخول)`، والرسوم نفس `fee` تبع الإعدادات.

### الإعدادات (`BOT.cfg`)
| المفتاح | الافتراضي | المعنى |
|---|---|---|
| `tf` | 15m | فريم الوكيل |
| `src` | watch | قائمتي أو أعلى 25 (`top`) |
| `minStr` | 60 | أقل قوة ترند ليسأل الوكيل |
| `maxOpen` | 3 | أقصى صفقات مفتوحة لكل حساب |
| `risk` / `lev` | 1% / 10 | المخاطرة وأقصى رافعة |
| `maxCalls` | 40 | أقصى طلبات AI باليوم (القرارات والدروس) |
| `start` | 1000 | الرصيد الوهمي |
| `rules` | ✓ | تشغيل بوت الإشارات للمقارنة |

### التخزين
`localStorage["frp_bot"]` = `{on, cfg, ai:{bal,pos,closed}, rules:{bal,pos,closed}, lessons, log, calls:{day,n}, lastBar, lastRun}`.

### ملاحظات
- لازم الصفحة تكون مفتوحة لحتى يفتح صفقات جديدة. الأداة بتطلب **Wake Lock** لحتى ما تنطفي الشاشة (إذا المتصفح بيدعمو).
- زر "صفّر الحساب" بيمسح الصفقات، وفيك تخلي الدروس.
- قارن **الوكيل** مع **الإشارات** بعد 50 صفقة عالأقل قبل ما تستنتج شي.
